STEP B / 比赛过程中

把变化留下来

  • 有代码：至少每 6 小时 push 一次，保留 GitHub 服务器端记录。
  • AI 创意：保留带任务 ID 和时间的生成记录、剪辑工程阶段截图。
  • 硬件：各关卡拍实机进度照片或视频。
  • 计划变化：保留原记录并说明调整，不要求每小时打卡。
已有项目可以继续开发。如实存档只影响「48 小时新增成果」15 分这一维度，其他维度照常评分。存档不对外公开，不改变知识产权归属。
存档时，各类作品分别补哪些基线证据？
  • 代码 / 固件：GitHub 链接＋完整 40 位 commit ID＋commit 页面截图。私有仓库须在 23:59 前邀请组委会账号（开营公布）；确实无法用仓库，交当前源码包。查 ID 可运行 git rev-parse HEAD。
  • AI 创意：已有素材清单、显示修改时间的文件夹截图、已有分镜或剧本、自有 IP 说明；没有就写「无」。
  • 硬件 / 联动：3—5 张照片，含元器件拆散全家福与已有原型多角度照片；已有固件按代码要求提交。可由工作人员代拍上传。
  • 从零开始：空仓库 / 脚手架也登记 commit ID；无仓库交空工程截图。原文列出的替代方式为勾选承诺。

工作人员检查材料齐全、可打开后盖章并记录提交编号；17 日 00:00 锁定存档快照。已有成熟产品的品牌队伍进入新品组单独评选。隐瞒已有成果须经事实核实、申辩与复核，可能取消评奖资格。
